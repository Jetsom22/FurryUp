# 마스터 시트

강사가 채우는 원본이다. **`node tools/make-sheet.mjs`가 만든다** — 수강생이 낸 두 CSV에서 ID·타입·스탯·원안 서술을 옮겨 오고, 규격 칸만 비워 둔다.

구글 시트에 올려 쓰고, `npm run sheet:pull`로 당겨온다. 탭 이름과 파일 이름이 같아야 한다.

| 탭 | 행 | 누가 채우나 |
|---|---|---|
| `character` | 42 | 수치와 키만 든다. 강사는 `rarity` |
| `skill_group` | 42 | 채워져 있다. 공용 풀을 쓰면 `basic2`를 손본다 |
| `skill` | 115 | **여기가 일이다.** `tier` `speed`와 빈 `element` `target` |
| `skill_effect` | 0 | **여기가 일이다.** 효과 한 줄에 한 행 |
| `string` | 392 | **게임에 나가는 모든 글자.** 번역은 여기서만 한다 |
| `resource` | 126 | 캐릭터 셋은 기계가 만든다. 배경·아이콘은 사람이 적는다 |

<br>

## 머리글이 세 줄이다

| 줄 | 무엇 |
|---|---|
| 1 | 한국어 라벨. 사람이 읽는다 |
| 2 | **칼럼명. 변환기가 읽는 유일한 줄이다** |
| 3 | 타입 |

라벨은 마음대로 고쳐도 된다. 칼럼명을 고치면 변환기가 그 칸을 못 찾는다.

<br>

## 역할군 칸

`character` 탭의 `role`은 일곱 코드 중 하나다. `ASSASSIN` `HUNTER` `CHARGER` `GUARDIAN` `TRICKSTER` `CLOSER` `HEALER` 이고, 뜻은 `design/00_overview.md`의 역할군 절에 있다.

**제출물에는 없는 칸이다.** 이관하며 사람이 정했으므로 `npm run sheet`가 다시 만들어도 적힌 값을 그대로 지킨다. 비워 두면 변환기가 막는다.

<br>

## 허브가 둘이다

**글자는 `string`에서만, 파일은 `resource`에서만 나온다.** 다른 탭은 키만 든다.

`character`의 `name` `desc` `story` `species` 칸에 들어 있는 것은 글자가 아니라 **`string` 탭의 키**다. `res` 칸은 `resource` 탭을 가리킨다. 스트링 표를 만든 이유가 "문구를 한곳에서 검수하고 번역한다"인데, 이름이 여러 탭에 흩어져 있으면 번역자에게 시트를 줄 수가 없다.

키를 칸에 직접 적는다. 기계가 `CHR_001` + `_NAME`으로 지어내지 않는다 — 그러면 규칙이 시트와 코드 두 곳에 살고, 시트를 보는 사람은 어느 문구가 걸리는지 알 수가 없다.

리소스는 반대로 **규격을 표가 가른다.** `character`는 `RES_CHR_001` 하나만 들고, 정면·후면·초상·컷씬은 `resource` 탭이 `kind`로 나눈다. 나중에 UI 아이콘과 배경이 들어와도 쓰는 쪽은 그대로다.

대신 사람이 어느 행인지 알아보라고 **`_`로 시작하는 칸**을 둔다.

| 칸 | 무엇 |
|---|---|
| `_name` | `string` 탭을 비추는 수식. 고쳐도 아무 데도 안 간다 |
| `_owner` | 어느 캐릭터 것인지 눈으로 짚으라고 둔 메모 |
| `_source` | 수강생이 쓴 원안. 게임에 안 나간다 |
| `_hint` | 기계가 원안에서 찾아낸 할 일 |
| `_concept` | 전투 컨셉. 기획 의도라 게임에 안 나간다 |
| `_hold` | 스탯·기술이 모자란 곳 |

**`_` 칸은 변환기가 아예 읽지 않는다.** 읽으면 두 번째 진실이 생긴다.

`_owner`가 참조가 아닌 이유도 같다. `character → skill_group → skill`로 이미 닿는데 `skill → character` 화살표를 하나 더 그으면 참조가 되돌아온다.

<br>

## 효과는 그룹으로 묶는다

`skill`의 `effect_group` 칸이 `skill_effect`의 같은 이름 칸을 가리킨다.

**재사용하려는 것이 아니다.** 어떤 기술은 효과가 하나이고 어떤 기술은 셋이라, 칸을 옆으로 펴면 넷에서 막히고 다섯 번째가 필요한 날 표를 고쳐야 한다. 그룹 키 하나를 걸어 두면 행을 더하는 것으로 끝난다.

`skill_effect.id`는 **인조 식별자**다. `(effect_group, seq)`를 키로 삼으면 순서를 바꿀 때마다 키가 움직인다.

<br>

## 키 앞자리는 눈으로 짚으라고 있다

`SKL_1003`이 `CHR_003`의 일반기다. 1·2는 일반기, 5는 특수기, 7은 패시브.

**판정이 읽는 것은 `slot` 칸이다.** 키 범위는 편의일 뿐이고 둘이 어긋나면 검사기가 말해 준다. 키에 두 역할을 주면 나중에 어느 쪽이 진실인지 아무도 모르게 된다.

<br>

## 규격을 어떻게 채우나

`skill._source`에 수강생이 쓴 원안이 그대로 있다. 그것을 보고 규격 칸을 채운다.

`skill._hint`는 기계가 원안에서 찾아낸 것이다 — `확률 30%`, `우선`, `조건 same_type`, `초 단위 — 턴제라 버린다`. **값이 아니라 할 일 목록**이라, 힌트가 있으면 그 자리를 어떻게 옮길지 정해야 한다는 뜻이다.

점수는 [설계 도구](../../docs/build.html)에서 본다. 규격을 넣어 보고 예산 안에 드는지 확인한 뒤 시트에 옮긴다.

패시브는 속성을 안 문다. `element`를 비워 두는 것이 곧 그 뜻이다.

<br>

## 되읽기

```bash
npm run sheet          # 시트를 다시 뽑는다. 채운 것은 지키고 원안만 갱신
npm run sheet:pull     # 구글 시트 → sheets/master/*.csv
npm run sheet:push     # sheets/master/*.csv → 구글 시트
npm run sheet:diff     # 둘이 얼마나 벌어졌는지만 센다
npm run sheet:check    # 검사만. 무엇이 모자란지 말해 준다
npm run rules:import   # rule 과 grade 를 판정이 읽는 모듈로 내린다
npm run sheet:import   # 통과하면 docs/data/ 를 갈아 끼운다
```

<br>

### 미는 쪽

`sheet:push`가 탭을 통째로 갈아 끼운다. 스키마가 바뀌었을 때와 리포에서 수치를 고쳤을 때 쓴다. 평소 채우기는 시트에서 하고 리포는 `sheet:pull`로 받는다.

**어느 쪽이 뒤에 있는지는 `npm run sheet:diff`가 말한다.** 행 수나 수정 시각으로는 못 잰다. 사람이 채우는 것은 새 행이 아니라 빈칸이고, 리포에서 고치는 것은 이미 있는 칸의 값이다. 둘 다 행 수를 안 바꾼다.

붙이려면 시트에 Apps Script 웹 앱을 한 번 배포해야 한다. 방법은 [`tools/apps-script/README.md`](../../tools/apps-script/README.md). 구글 드라이브 API로는 셀을 못 고쳐서(파일 이름과 폴더 위치만 바뀐다) 이 길이 필요하다.

**밀기 전에 먼저 읽어 본다.** 시트에서 사라질 값이 하나라도 있으면 거부하고 무엇이 어디에 있는지 말해 준다. 비어 있던 칸이 채워진 것뿐 아니라 **값이 달라진 것도 센다** — 시트에서 5를 6으로 고쳤는데 리포가 아직 5를 들고 있으면 미는 순간 소리 없이 5로 돌아가기 때문이다.

그때 할 일은 `sheet:pull`이다. 일부러 덮는 것이면 `--force`.

되돌리는 것은 시트의 **파일 › 버전 기록**이다.

웹 앱을 아직 안 붙였으면 xlsx로 올려도 된다.

```bash
python3 tools/gen-xlsx.py      # sheets/master/*.csv → master.xlsx (탭 여섯)
```

나온 파일을 구글 시트에서 **파일 › 가져오기 › 새 시트 삽입**으로 올리면 탭 여섯이 한 번에 들어간다. 머리글 세 줄에 색이 붙고 `_` 칸이 회색으로 칠해져 나오므로, 어느 칸이 기계용이고 어느 칸이 메모인지 눈으로 갈린다. 처음 한 번은 이쪽이 낫다 — 서식이 같이 들어가고, `sheet:push`는 서식을 안 건드린다.

**되받을 때는 CSV로 받는다.** xlsx를 리포에 두면 `git diff`가 안 보인다. 그래서 `master.xlsx`는 `.gitignore`에 있다.

<br>

`sheet:pull`을 쓰려면 `source.json`에 시트 ID와 탭 gid를 적고, 시트를 **"링크가 있는 사람에게 보기"**로 둔다. 인증이 필요 없어지고 굴려야 할 비밀값도 안 생긴다. 이 시트에는 개인정보가 없다 — 제출자 칸이 없고 캐릭터명·컨셉·스탯뿐이라 어차피 게임에 공개될 것들이다.

**배포 파이프에는 넣지 않는다.** 넣으면 시트를 고치는 순간 아무도 모르게 라이브가 바뀐다. 리포에 올라온 CSV가 배포 시점의 진실이어야 한다.

**저장 형식은 CSV로 남긴다.** xlsx로 두면 `git diff`가 안 보여서 "어제보다 얼마나 채웠나"를 알 수 없다. 채우는 일이 며칠에 걸치므로 그게 중요하다.

**검사가 기본이다.** 덜 채워진 것은 오류가 아니라 할 일로 나오고, 규격을 어긴 것만 오류다. 키와 슬롯이 어긋난 것처럼 사고에 가까운 것은 따로 짚어 준다. 그리고 규격을 갖춘 종이 여섯 미만이면 아예 쓰지 않는다 — 빈 로스터로 갈아 끼우면 게임이 통째로 죽는다.

**기계가 규격을 채우지 않는다.** 서술을 규격으로 옮기는 것은 판단이고, 기계가 찍으면 그 값이 검토 없이 통과한다.

<br>

## 다시 뽑아도 채운 것은 안 지운다

`make-sheet.mjs`를 다시 돌려도 **사람이 채우는 칸은 그대로 둔다.** 스탯, 희귀도, 규격 칸, 문구, 경로가 그렇다. 시트에만 있는 행(효과, 사람이 더한 문구)도 뒤에 그대로 붙는다.

기계가 매번 다시 쓰는 것은 키·슬롯·원안·힌트다. 원본 제출이 고쳐지면 그쪽이 갱신된다.

구글 시트 쪽에서 채우는 중이라면 **`npm run sheet:pull`을 먼저 돌린다.** 안 그러면 리포에 있는 오래된 CSV를 기준으로 지킨다.

`pull → pull`도, `pull → sheet`도 같은 파일을 낸다. 그래서 `git diff`에 뜨는 것은 언제나 **실제로 바뀐 것뿐**이다. 거울 칸이 그 성질을 깨뜨릴 뻔했다 — 시트에서 당겨오면 수식이 계산된 글자로 돌아와서, 그대로 두면 당겨올 때마다 157줄이 바뀐 것처럼 보였다. 당겨오면서 수식으로 되돌린다.

<br>

## 손으로 고치지 않는 것

`sheets/character.csv`와 `sheets/battle.csv`는 수강생 제출 원본이다. 거기서 고칠 것이 있으면 원본 시트에서 고치고 다시 내보낸다.

종족 표기만 예외다. 제출 칸이 자유 기술이라 띄어쓰기와 괄호 부연이 갈렸고, 여섯은 비어 있었다. 정리안은 `tools/make-sheet.mjs`의 `SPECIES_FIX`에 있다 — 빈 칸 여섯은 로그라인과 배경에 적힌 것을 옮겼으므로 **확인이 필요하다.**
