# 퍼리업 (FurryUp) 전투 프로토타입

전투 기획서 Ver01 · 스테이지 기획서 V0.2 · 정비 화면 기획서 Ver01 을 바탕으로
"전투가 굴러가는" 최소 루프를 웹에서 검증하기 위한 프로토타입입니다.

- 16:9 (1920×1080) PC 게임 기준 화면. 브라우저 창 크기에 맞춰 비율 유지 스케일
- Phaser 3 (로컬 파일 `vendor/phaser.min.js`), 빌드 도구 없음
- 캐릭터 리소스: `_DONE` 임시 리소스 25종

## 실행

정적 파일이라 아무 웹서버로든 열 수 있습니다. (브라우저 보안 정책 때문에 `file://` 로 직접 여는 것은 권장하지 않음)

```bash
# 방법 1
npx serve .
# 방법 2
python3 -m http.server 8080
```

이후 `http://localhost:8080` (또는 안내된 주소) 접속.

## 배포

빌드 단계가 없는 순수 정적 사이트라 저장소 루트를 그대로 올리면 됩니다.

- **GitHub Pages**: `.github/workflows/pages.yml` 이 `main` 브랜치 push 시 루트를 그대로 배포합니다.
  저장소 Settings → Pages → Source 를 **GitHub Actions** 로 선택하면 됩니다.
- **Cloudflare Pages**: 저장소 연결 후 Build command 비움, Build output directory `/` (루트) 로 설정.

## 플레이 흐름 (구현 범위)

```
아웃게임(타이틀) → 플레이 → 챕터 선택(1챕터만 열림) → 도전
  → 첫 동료 선택 (25종 중 7종 잠금, 18종 중 1마리)
  → 팀 편성 (편성 순서 1~5)
  → [스테이지 진입]  스토리 / 이벤트 / 전투(일반·중간보스·보스)
  → 클리어 → 정비 화면 (상점에서 캐릭터 구매 · 배치 · 부활 · 맵) → 다음 스테이지
  → … → 1-15 보스 클리어 → 아웃게임  /  전멸 → 아웃게임
```

### 전투 (전투 기획서)
- 화면 구성은 p.9 UI 와이어프레임의 10개 요소를 1920×1080 으로 환산해 그대로 배치
  (챕터/스테이지, 턴 수, 행동 순서(안내+이미지), 진행 로그, 캐릭터 명, 투지, 이미지, 설정, 남은 적, 진행 시작 버튼)
- 행동 순서: 우선도 → 속도 → 편성 순서 → 플레이어 캐릭터 우선 (p.7)
- 공격 대상: 편성 순서 1번부터. 암살자는 편성 순서가 가장 낮은 적부터 (p.6/p.8)
- 투지가 스킬 요구치 이상이면 스킬, 아니면 일반 공격. 공격 후 투지 상승 (p.6 플로우)
- 아군 체력 0 → 행동 비활성화(화면에 남음), 적 사망 → 화면에서 제거, 적 0 → 클리어, 아군 0 → 실패 (p.5)
- 역할군 효과 5종 (p.8): 보호자 보호막 10% / 돌격자 처치 시 5% 회복 / 결전자 8턴 이후 강화 / 교란자 15% 회피 / 암살자 후순위 타격
- 진행 시작 버튼은 진입 후 1회만 클릭 가능, 이후 비활성화. 설정 팝업에서 진행 속도(x1/x2/x4) 변경 가능

### 스테이지 (스테이지 기획서 / 1챕터 배치 조건)
- 15 스테이지: 1-1 스토리, 1-2 일반 고정, 1-14 스토리, 1-15 보스 고정
- 중간보스는 1-8~1-13 랜덤, 이벤트 4개는 1-3~1-13 랜덤 (3연속 금지), 나머지 일반 7
- 이벤트 하위 효과: 도박 25 / 이로운 45 / 해로운 20 / 일반 10 (%)
  첫 이벤트는 이로운·도박만, 해로운은 챕터당 최대 2회, 중간보스 이후 해로운 제외
- 상점(정비)은 보스 제외 모든 스테이지 클리어 후 등장

### 정비 화면 (정비 화면 기획서)
- 구현: 도감, 캐릭터 칸 1~5, 캐릭터 배치, 부활(골드), 맵, 골드, 상점(캐릭터 4종 판매), 리롤, 상점 닫기, 다음 스테이지
- **미구현(범위 외)**: 유물, 버프, 아이템(경험치), 칸 강화. 버튼만 비활성으로 배치

## 데이터 / 임시 수치 조정

기획서에 없는 수치는 전부 `data/` 아래 파일에서 바꿀 수 있습니다.

| 파일 | 내용 |
| --- | --- |
| `data/characters.js` | 캐릭터 25종: 임시 이름, 역할군, HP/공격/방어/속도, 잠금 여부, 스킬명 |
| `data/balance.js` | 투지/스킬, 데미지 공식, 역할군 효과 수치, 적 배율, 골드/가격, 이벤트 효과, 연출 속도 |
| `data/stages.js` | 챕터별 스테이지 수·고정 배치·랜덤 구간, 이벤트 확률/제약, 스토리 대사 |
| `data/enemies.js` | **적 편성 (임시)**. 확정 적 리스트를 받으면 이 파일만 교체 |

임시 공식
- 데미지 = max(1, floor(공격력 × 배율) − 방어력). 스킬 배율 1.8, 스킬 요구 투지 3, 공격마다 투지 +1 (최대 5)
- 적 능력치 = 기본 × 0.8 × (1 + 0.035 × (스테이지 번호 − 1)), 중간보스 HP×1.8, 보스 HP×3.0

### 적 리스트 넣는 법 (`data/enemies.js`)

```js
window.ENEMY_FORMATIONS = {
  // 스테이지 번호: 배열 순서 = 적의 편성 순서(1번부터)
  3: [
    { id: 'CHR_012', name: '검은 나방' },                 // 스탯 생략 시 characters.js 값 × 스테이지 배율
    { id: 'CHR_021', name: '독전갈', hp: 90, atk: 22, def: 5, spd: 12, role: '암살자' },
  ],
  15: [ { id: 'CHR_026', name: '들판의 폭군', boss: true }, ... ],
};
```
고정 편성이 없는 스테이지는 `ENEMY_POOL` + `ENEMY_COUNT_BY_STAGE` 규칙으로 랜덤 생성됩니다.

## 구조

```
index.html            진입점 (스크립트 로드 순서)
vendor/phaser.min.js  Phaser 3.80.1
assets/characters/    임시 캐릭터 리소스 (CHR_xxx_ST_F.png)
data/                 기획 수치 (위 표)
src/core/             렌더링과 분리된 순수 로직
  rng.js              시드 난수
  stagegen.js         스테이지 배치 / 이벤트 하위 효과 결정
  battle.js           전투 엔진 (턴 → 이벤트 배열)
  run.js              런 상태 (보유/편성/골드/상점/부활/이벤트 효과)
src/ui/theme.js       공용 UI 헬퍼
src/flow.js           씬 전환 규칙
src/scenes/           Boot / Title(아웃게임) / Pick / Formation / Battle / Story / Event / Shop
tests/engine.test.js  전투·스테이지 규칙 단위 테스트 (node)
```

## 테스트

```bash
node tests/engine.test.js
```
행동 순서, 공격 대상, 데미지/투지/스킬, 역할군 효과, 전멸 판정, 스테이지 배치 제약, 상점/부활/이벤트 효과를 검증합니다.

## 디버그 팁

- 브라우저 콘솔에서 `game.registry.get('run')` 으로 현재 런 상태(골드, 편성, 스테이지 목록, 시드)를 볼 수 있습니다.
- 전투 중 `game.scene.getScene('BattleScene').battle` 로 유닛 상태 확인 가능.
- 정비 화면의 **맵** 팝업은 프로토타입 편의상 챕터 전체 배치(중간보스 위치 포함)를 공개합니다.
