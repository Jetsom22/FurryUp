# 퍼리업 (FurryUp) 전투 프로토타입

전투 기획서 Ver01 · 스테이지 기획서 V0.2 · 정비 화면 기획서 Ver01 을 바탕으로
"전투가 굴러가는" 최소 루프를 웹에서 검증하기 위한 프로토타입입니다.
캐릭터·기술·판정 수치는 **로켓몬스터 원본 마스터 데이터**(42종)를 그대로 가져와 씁니다.

- 16:9 (1920×1080) PC 게임 기준 화면. 브라우저 창 크기에 맞춰 비율 유지 스케일
- Phaser 3 (로컬 파일 `vendor/phaser.min.js`), 빌드 도구 없음
- 라이브: https://jetsom22.github.io/FurryUp/

## 실행

정적 파일이라 아무 웹서버로든 열 수 있습니다. (`file://` 직접 열기는 브라우저 보안 정책 때문에 권장하지 않음)

```bash
npx serve .            # 또는
python3 -m http.server 8080
```

## 배포

빌드 단계가 없는 순수 정적 사이트라 저장소 루트를 그대로 올리면 됩니다.

- **GitHub Pages**: `.github/workflows/pages.yml` 이 `main` push 시 테스트 후 루트를 배포합니다. (Settings → Pages → Source: GitHub Actions)
- **Cloudflare Pages**: Build command 비움, Build output directory `/`.

## 플레이 흐름 (구현 범위)

```
아웃게임(타이틀) → 플레이 → 챕터 선택(1챕터만 열림) → 도전
  → 첫 동료 선택 (42종 중 12종 잠금, 30종 중 1마리)
  → 팀 편성 (편성 순서 1~5)
  → [스테이지 진입]  스토리 / 이벤트 / 전투(일반·중간보스·보스)
  → 클리어 → 정비 화면 (상점에서 캐릭터 구매 · 배치 · 부활 · 리롤 · 맵) → 다음 스테이지
  → … → 1-15 보스 클리어 → 아웃게임  /  전멸 → 아웃게임
```

### 전투 (전투 기획서 + 원본 판정 규칙)
- 화면은 p.9 UI 와이어프레임의 10개 요소를 1920×1080 으로 환산해 그대로 배치
- **행동 순서**: 우선 행동(haste) → 우선도 → 속도(+기술 속도 보정) → 편성 순서 → 플레이어 캐릭터 우선 (p.7)
- **공격 대상**: 편성 순서 1번부터. 암살자는 가장 낮은 순서, 추격자는 체력 비율이 가장 낮은 적. 도발 중인 적이 있으면 그쪽 (p.6/p.8)
- **투지**: 일반기 사용 후 +1, 특수기는 기술의 투지 비용(1~6) 이상일 때 사용 후 차감. 상한 6 (`RULES.SP_*`)
- **데미지** = (공격 or 마법 + 8) × 속성 계수(야성/비술/신성 × 일반/특수) × 위력단계(0~10) × 방어 경감 × 타입 상성(육▶공▶해▶육, 1.8 / 0.6) × 처형·표식 등 배율
  - 방어 경감 = SCALE / (SCALE + 방어 × 6). SCALE 은 물리 45, 마법 52. 신성은 방어를 무시
  - 계수·위력 사다리·상성 배율은 전부 `data/rules.js` (원본 `rule.csv`), 방어 가중치 6 만 `data/balance.js` 의 임시값
- 아군 체력 0 → 행동 비활성화(화면에 남음), 적 사망 → 화면에서 제거, 적 0 → 클리어, 아군 0 → 실패 (p.5)
- 진행 시작 버튼은 진입 후 1회만 클릭 가능. 설정 팝업에서 속도(x1/x2/x4) 변경 가능

### 역할군 (원본 7종)
| 역할군 | 효과 (전투 기획서 p.8 / 임시) |
| --- | --- |
| 암살자 | 편성 순서가 가장 낮은 적 우선 공격 |
| 보호자 | 스테이지 시작 시 최대 체력의 10% 보호막 |
| 돌격자 | 적 처치 시 현재 체력의 5% 회복 |
| 결전자 | 턴 8 이상 진행 시 공격/물방/마방 +2 |
| 교란자 | 15% 확률로 공격 회피 |
| 추격자 (임시) | 체력 비율이 가장 낮은 적 우선 공격, 잃은 체력에 비례해 최대 +30% |
| 치유자 (임시) | 턴 종료 시 가장 다친 아군을 최대 체력의 5% 회복 |

### 기술 효과 키워드
원본 45종 중 프로토타입이 판정에 반영하는 것: **회복, 보호, 흡혈, 연타, 투지획득, 투지전달, 투지흡수, 반동, 대가, 처형, 사투, 팽창, 투기, 관통, 공성, 투과, 설욕, 각성/쇠약, 출혈, 표식, 기절, 침묵, 도발, 우선, 퇴장** (25종).
나머지(특효, 정화, 포식, 부패, 실명, 간파, 수호, 전환, 버팀, 면역, 벼림, 가호, 응혈, 갱신, 잔류, 제물, 고양, 원한, 격차, 상성완화)는 설명만 표시하고 판정에는 넣지 않습니다. 패시브 기술도 표시만 합니다(역할군 효과가 그 자리를 대신).
지원 목록은 `src/core/battle.js` 의 `SUPPORTED` 배열입니다.

### 스테이지 (스테이지 기획서 / 1챕터 배치 조건)
- 15 스테이지: 1-1 스토리, 1-2 일반 고정, 1-14 스토리, 1-15 보스 고정
- 중간보스는 1-8~1-13 랜덤, 이벤트 4개는 1-3~1-13 랜덤 (3연속 금지), 나머지 일반 7
- 이벤트 하위 효과: 도박 25 / 이로운 45 / 해로운 20 / 일반 10 (%). 첫 이벤트는 이로운·도박만, 해로운은 챕터당 최대 2회, 중간보스 이후 해로운 제외
- 상점(정비)은 보스 제외 모든 스테이지 클리어 후 등장

### 정비 화면 (정비 화면 기획서)
- 구현: 도감, 캐릭터 칸 1~5, 캐릭터 배치, 부활(50G), 맵, 골드, 상점(캐릭터 4종), 리롤(10G), 상점 닫기, 다음 스테이지. 상인은 안내자(CHR_901)
- **미구현(범위 외)**: 유물, 버프, 아이템(경험치), 칸 강화. 버튼만 비활성으로 배치

### 원본 표를 고쳤을 때
```bash
node tools/import-rocketmonster.js <꾸러미 경로>      # 그림까지 다시 복사
node tools/import-rocketmonster.js                    # data/source/rocketmonster/ 기준으로 데이터만 재생성
node tests/engine.test.js
```
잠금 12종은 변환기의 `LOCKED` 목록(현재 CHR_031~042)에서 바꿉니다.

### 적 리스트 넣는 법 (`data/enemies.js`)
```js
window.ENEMY_FORMATIONS = {
  3: [ { id: 'CHR_012', name: '검은 나방' }, { id: 'CHR_021', hp: 120, atk: 7 } ],   // 배열 순서 = 편성 순서
  15: [ { id: 'CHR_012', name: '들판의 폭군', boss: true }, ... ],
};
```
고정 편성이 없는 스테이지는 `ENEMY_POOL` + `ENEMY_COUNT_BY_STAGE` 규칙으로 랜덤 생성됩니다.
적 능력치 = 원본 × 0.85 × (1 + 0.035 × (스테이지 − 1)), 중간보스 HP×1.8, 보스 HP×3.0 (`data/balance.js` ENEMY).

## 디버그 팁

- 콘솔에서 `game.registry.get('run')` 으로 현재 런 상태(골드, 편성, 스테이지 목록, 시드) 확인
- 전투 중 `game.scene.getScene('BattleScene').battle` 로 유닛 상태(투지, 상태이상) 확인
- 정비 화면의 **맵** 팝업은 프로토타입 편의상 챕터 전체 배치(중간보스 위치 포함)를 공개합니다
